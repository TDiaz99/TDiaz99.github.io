Webhook events

Meridian posts a signed JSON payload to your endpoint whenever something you subscribe to happens.

Available events

Event Fires when
employee.created An employee record is created
employee.updated Any field on a record changes
employee.terminated A final working date is recorded
payrun.prepared A pay run finishes calculating
payrun.approved A pay run is approved and locked
payrun.paid Payments have been released
timeoff.requested An employee requests leave
timeoff.approved A manager approves leave

employee.updated is deliberately broad and fires often. Check the changed array rather than reacting to every one.

Payload shape

Copy
employee.updated
{
  "id": "evt_3PqR7x",
  "type": "employee.updated",
  "created_at": "2026-08-04T09:14:22Z",
  "data": {
    "id": "emp_8Kd21",
    "legal_name": "A. Okafor",
    "pay_group": "pg_monthly_salaried"
  },
  "changed": ["pay_group"]
}

Register an endpoint

  1. Go to Settings > Webhooks and select Add endpoint.

  2. Enter an HTTPS URL. Plain HTTP is rejected.

  3. Choose the events to subscribe to.

  4. Copy the signing secret. It is shown once and cannot be retrieved later.

If you lose the signing secret you must rotate it, which invalidates the old one. Store it with your other application secrets when you create the endpoint.

Verify the signature

Each request carries an X-Meridian-Signature header: a timestamp and an HMAC-SHA256 of timestamp + "." + body, keyed with your signing secret.

Copy
Verifying in Node.js
const crypto = require('crypto');

function verify(header, rawBody, secret) {
  const [ts, sig] = header.split(',').map(p => p.split('=')[1]);

  // Reject anything older than five minutes to stop replay attacks.
  if (Math.abs(Date.now() / 1000 - Number(ts)) > 300) return false;

  const expected = crypto
    .createHmac('sha256', secret)
    .update(ts + '.' + rawBody)
    .digest('hex');

  return crypto.timingSafeEqual(Buffer.from(sig), Buffer.from(expected));
}

Verify against the raw request body, before any JSON parsing. Re-serialising the body changes the bytes and the signature will never match.

Retries

Return 2xx quickly to acknowledge. Anything else, or a timeout after 10 seconds, is treated as a failure and retried.

Attempt Delay after the previous try
2 1 minute
3 5 minutes
4 30 minutes
5 2 hours
5 12 hours

After six failures the endpoint is disabled and the account owner is emailed.

Acknowledge first, process afterwards. Write the event to a queue and return 200 straight away, so slow processing never causes a retry.

Delivery is at-least-once, so the same event can arrive twice. Treat the event id as an idempotency key and ignore ones you have already handled.
